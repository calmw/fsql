## 索引

#### 键值存储和关系数据库

- 数据库索引主要是关于范围查询和点查询的。范围查询是点查询的一个超集
- 一个数据库系统可以建立在一个KV存储器上

#### 哈希表

- 在设计简直存储时，跳表首先被排除，主要原因是排序，现实世界的很多应用程序确实需要排序
- 也可以在专门的应用程序中使用散列表。使用散列表的另一个令人头疼的问题是调整大小的操作。初始调整大小为O (n)
  ，并导致磁盘空间和IO的突然增加。可以逐步调整散希表的大小，但这会增加
  复杂性

#### B树

- 平衡的二进制树(binary tree)可以在 O(log(n)) 中进行查询和更新，并且可以进行范围查询。binary tree大致是一个平衡的n元树。为什么要使用
  n-ary tree
  而不是binary tree呢？原因有以下几个：
  > 1.空间开销更小。   
  父树中的每个叶节点都通过来自父节点的指针到达，父节点也可能有一个父节点。平均每个叶节点需要1个~2个指针。
  这与b树相反，在b树中，一个叶节点中的多个数据共享一个父节点。n-ary tree也更短。在指针上浪费的空间更少。
  >
  > 2.内存更快。  
  由于现代CPU内存缓存和其他因素，n-ary tree可以比二进制树更快，即使它们的大o复杂度相同。
  >
  > 3.更少的磁盘IO。  
  binary tree更短，这意味着更少的磁盘搜索。
  磁盘IO的最小大小通常是内存页的大小（可能为4K)
  。即使你阅读一个更小的页面，操作系统也会填满整个4K页面。如果我们利用一个4K页面中的所有信息(通过选择
  至少有一个页面的节点大小)。
  我们将在这本书中使用binary tree。但是binary tree并不是唯一的选择。

#### LSM-Trees(Log-structured merge-tree)

- 日志结构化合并树。下面是对LSM-Tree操作的高级概述。如何查询：
    - 1.一个LSM-Tree包含多个级别的数据。
    - 2.每个级别都被排序并分割成多个文件。
    - 3.点查询从顶层开始，如果没有找到键，搜索将继续到下一层。
    - 4.范围查询合并了来自所有级别的结果，而更高的级别在合并时具有更多的优先级。
    - 如何更新：
    - 5.更新键时，键首先从顶层插入到文件中。
    - 6.如果文件大小超过了一个阈值，请将其与下一级别合并。
    - 7.文件大小阈值随着每个级别呈指数级增长，这意味着数据量也呈指数级增长。

- 让我们来分析一下这是如何工作的。对于查询：
    - 1.每个级别都是排序的，键可以通过二进制搜索找到，而范围查询只是
      顺序文件。这是e伍cient。有关更新：
    - 2.顶级文件的大小很小，所以插入到顶层只需要少量的IO。
    - 3.数据最终会被合并到一个较低的级别。合并是连续的IO，这是一个优势。
    - 4.更高的级别更经常地触发合并，但合并也更小。
    - 5.当将文件合并到较低级别时，其范围相交的任何较低文件都会被合并的结果替换（可以是多个文件）。我们可以看到为什么级别被分割成多个文件——以减少合并的大小。
    - 6.合并可以在后台进行。然而，低级合并会突然导致高IO使用率，从而降低系统性能。
      读者在读完这本书后，可以尝试用LSM-trees来代替b-树。并比较b树和LSM树的优缺点。
